How onlymuse works

onlymuse is a Mac app for Apple Music. It shows Apple Music's pages, and YouTube Music's pages, in a window that it draws itself. Music.app plays every song, so the sound stays lossless.

These pages explain the code to a reader who has never seen it. Start with "Before you read" if Odin or a native renderer is new to you. Then read the parts in any order, or follow one click from start to end on the journey page.

Before you read

Each item explains one idea that the other pages use. Each one links to a longer guide.

Odin

The app is written in Odin, a language close to C. A procedure is a function. A package is a folder of .odin files that share their names. One package calls another with its folder name as a prefix, such as ui.box or helper.start. Odin has no classes and no garbage collector. Learn the syntax from the Odin overview.

Manual memory and temp memory

Odin frees no memory by itself. The code frees each thing it makes. An allocator is the object that gives out memory. Each thread has a temp allocator for short-lived things. The main thread frees all of its temp memory at the start of each frame, in begin_frame. So text that one frame makes in temp memory lasts until the next frame starts.

An arena is an allocator that frees everything it gave out at once. onlymuse reads the data of each page into an arena of its own. When a new answer comes, the page reads it into a new arena. The next frame frees the old arena, in retire_arena. See allocators in the Odin overview.

The frame loop

A game draws its screen many times a second. onlymuse does the same. macOS tells the app each time the screen refreshes, through a display link. On each refresh, the app runs draw_frame. When nothing moves, the app stops asking for frames, so it uses no power while it waits.

An immediate-mode UI

Most UI kits keep a tree of views and change the tree when the data changes. onlymuse builds the whole tree of boxes again on every frame, straight from its state. A box is one rectangle with a style, and maybe text. No code keeps the screen in sync with the data. The next frame shows the new data. A click comes back as a signal from ui.signal on the box that the code builds. Read Immediate mode GUI for the idea.

Metal

Metal is Apple's API for the GPU. onlymuse uses no AppKit buttons or text views on screen. It hands Metal a list of rectangles each frame. Each rectangle has a colour, round corners, and maybe a piece of a texture: a letter, a symbol or a cover. Shaders, small programs that run on the GPU, draw them. See Apple's Metal page.

Objective-C from Odin

AppKit and Metal are Objective-C APIs. Odin calls them with objc_send, which sends a message, such as "setPaused:", to an Objective-C object. The text in quotes is the method's name, its selector. Plain C APIs of macOS, such as CoreText and SQLite, live in src/mac. See objc_send in Odin's intrinsics package.

The helper process

Some macOS features are easy in Swift and hard in Odin: AppleScript, WebKit pages and the Keychain. So onlymuse starts a second program, the Swift helper in helper/. The two programs talk in JSON, one message per line, over the helper's standard input and output. The app starts it in helper.start.

SQLite

SQLite is a database in one file, with no server. onlymuse keeps its file in ~/Library/Application Support/onlymuse-native. It holds Apple's answers, the play log and the saved state of the window. See About SQLite.

Words

The pages use the project's own words. A song is one song. Music.app calls it a track. The catalog is everything Apple Music offers. The library is what the account added. A shelf is one named row on Home. A card is one tile on a shelf. The full list is in CLAUDE.md, under Words.

The window and a frame

This page tells how onlymuse opens its window and draws each frame. It covers the window, the box tree, the text, the icons, the covers and the look. Read these parts of the index page first: Odin, memory, the frame loop, the immediate-mode UI, Metal and Objective-C calls from Odin.

What you see

onlymuse opens one window of 1200 by 800 points (open_main_window). At zoom 1, the person can make it no smaller than 1000 by 600 points (MIN_WINDOW_WIDTH_POINTS). The window shows no title. Its content runs up under the traffic lights (FullSizeContentView).

The desktop shows through the window, blurred. A dark grey at 85 percent covers the blur (colors.window). Inside the window, the person sees four parts:

  • The sidebar on the left, 228 points wide, with the search field and the list of pages (build_sidebar).
  • The page area in the middle. A toolbar with the back and forward buttons runs along its top. The page the person opened fills the rest (build_page_area).
  • The side panel on the right, 320 points wide, with the Up Next and Lyrics tabs. It slides shut when the person closes it (build_panel).
  • The player bar along the bottom, 70 points tall (build_player_bar).

The song menu, the command palette, a toast and the sign-in card can float over these parts. AppKit gives the window, the blur and the keyboard. onlymuse draws every box, word and icon inside the window itself, with Metal.

How the window opens

main runs these steps in order:

  1. It sets the temp memory of a frame to 4 MB (MAIN_TEMP_BYTES).
  2. It starts the store, Apple, YouTube, the queue and navigation (start_parts). Then it starts the Helper.
  3. It opens the window (platform.open_window) and gives it draw_frame as the procedure for each frame.
  4. It starts render, font, icon and image.
  5. It hands control to AppKit's events (platform.run). This call returns only when the window closes.

open_window puts four views and objects together:

  • An NSWindow with a see-through background and a see-through title bar (make_ns_window).
  • A blur view as the window's content (make_blur_view). Each time AppKit updates the blur, onlymuse hides the layer that tints it with the desktop colour. It also drops the filter that raises its saturation (remove_layer_background).
  • A view with a CAMetalLayer, in front of the blur (make_metal_view). Metal draws every frame into this layer.
  • A display link that starts paused (make_display_link). It calls onlymuse once before each refresh of the screen.

onlymuse declares three Objective-C classes of its own in Odin. OMTarget takes the display link's calls and the window's resize and close. OMBlurView runs the blur. OMInputView takes typing. At the end, show_window asks for the first frame.

How a frame goes

onlymuse draws a frame only when something changes. The diagram follows one mouse move from AppKit to the screen. Step through it, or click a box to read its code.

When the frames stop

draw_frame returns true while it wants another frame. That happens during an animation of the UI, while a cover fades in, while the lyrics move and after an atlas starts over. A capture or bench run also wants every frame. When draw_frame returns false, run_frame pauses the display link. The app then uses no time until something wakes it:

  • request_frame unpauses the link. Each mouse, scroll and key event calls it. A resize of the window calls it too.
  • request_frame_after sets a timer, such as for the next word of a lyric line.
  • wake posts an event from another thread, such as when a cover finishes loading.

A test window behind the other windows gets no frames from its display link. A timer runs its frames 60 times a second instead (Target_frameTimerFired).

Events and typing

The event list lives for one frame. Two arenas take turns to hold the text of the events, so that text lasts through the next frame (run_frame). Any part of the app reads the list with list_events.

Typing in a text field goes another way. While a field has focus, a 1-point view takes the keys (Text_View). The macOS input method composes text in that view, such as kana before it becomes kanji. The view turns what it gets into Text_Insert, Text_Marked and Text_Command events. At the end of each frame, finish_text_fields gives the keys to that view, or back to the shortcuts.

What each package hands to the next

Each package in the frame does one job. Click a box to read it.

The box tree

The ui package is an immediate-mode UI (see the index). The app calls ui.box with an ID, a style and an optional text. The box goes in the current parent. ui.scope makes a box the parent of the boxes built inside its if.

Each box with an ID keeps its state from one frame to the next. Its key is a hash of its ID and its parent's key (to_key). The kept state holds the hover, the press and the scroll. A box with an empty ID lives in the temp memory of the frame and keeps nothing. A box that a frame does not build goes away at the end of that frame (remove_unbuilt).

A width or a height takes one of five kinds: points, a percent of the parent, a share of the free space, the size of the children, or the size of the text (Size_Kind). ui.end_frame lays out the tree in three passes:

  1. measure works from the bottom of the tree up. It shapes each text and works out the sizes that need no parent.
  2. resolve works from the root down. It shares the free space and wraps text to its width.
  3. place sets the rectangle and the clip of each box. A scroll box moves its children by its scroll.

Then find_hot finds the last clickable or hoverable box under the mouse. That box shows on top. The build code asks ui.signal if the person hovered or clicked a box. The hover that signal reads comes from the layout of the last frame.

A scroll moves the scroll target of the scroll box under the mouse (apply_events). A trackpad scroll jumps there at once. A mouse wheel scroll glides there over the next frames. ui.animate glides any number the same way, such as the width of the side panel.

Last, draw walks the tree. For each box, it pushes a rounded rectangle, then the text, then the box's own draw proc. The box's draw proc draws an icon or a cover.

Drawing with Metal

Each rectangle, glyph and image becomes one 128-byte instance (Instance). render.push groups the instances in a row that use the same texture. render.end_frame then draws each group with one call. It keeps three buffers, so the GPU can still draw a frame while the app builds the next one (FRAMES_IN_FLIGHT).

One pair of shaders draws every instance. The fragment shader works out rounded corners and borders from a distance to the box (fragment_main). For a glyph or an icon, it reads the coverage from the atlas. For a cover, it reads the colour from the cover's texture. The app compiles the shaders from their source when it starts (render.start).

Text

The font package uses San Francisco, the system font of macOS (system_font). font.shape asks CoreText for the glyphs of a text and their places. It also breaks the text into lines, or ends it in "…". It keeps each result until no frame uses it for 120 frames.

font.draw pushes one instance per glyph. Each glyph comes from one texture of 4096 by 4096 pixels, the atlas. The first time a glyph shows, rasterize draws it with CoreText as a grey mask and copies it into the atlas. The atlas holds each glyph at up to four positions within a pixel (SUBPIXEL_STEPS). When the atlas fills up, it starts over and asks for one more frame.

SF Symbols work the same way in the icon package. AppKit draws each symbol once per size into an atlas of 1024 by 1024 pixels (rasterize). The atlas keeps only the mask, so the shader can fill the symbol with any colour.

Covers

A cover goes on the screen through artwork_rect_box. The box first shows a placeholder, a gradient with a symbol on it. Its draw proc, draw_artwork, asks image.watch for the texture each frame. watch returns nothing until the cover loads. Then the cover fades in over 0.25 seconds.

The image package loads covers on six worker threads (WORKER_COUNT). fetch_image downloads a cover once to ~/Library/Caches/onlymuse-native/images. read_texture decodes it straight to the size the window draws and crops it to the box. It also works out the colour of the cover. Then the thread wakes the event loop.

At the start of each frame, image.begin_frame takes in the finished covers and starts the next ones. A cover the person scrolled past waits. A loaded size of the same cover stands in while a new size loads (find_stand_in). The GPU keeps at most 64 MB of covers. Above that, unload_extra unloads the covers that no frame drew for the longest time. It never unloads a cover the last frame drew.

The look

The app/kit package holds the look of the window. Every page builds with it.

  • The colours of the design mock, in colors. The file also names the sizes of the sidebar, the player bar, the toolbar and the panel.
  • The accent colour. update_accent turns it each frame toward the colour of the cover of the Now playing song. With no colourful cover, it turns to the system accent that the Helper sends.
  • The widgets: icon_button, action_button, scrolling_text, page_scroll, build_text_field, menu_box and build_toast. Each one puts boxes in the tree. A button returns true when the person clicks it.

Where the code is

  • src/app/main.odin starts every part and opens the window.
  • src/app/frame.odin builds one frame.
  • src/platform/open_window.odin makes the window, its views and the display link.
  • src/platform/window.odin runs the events, the display link and the timers.
  • src/platform/events.odin turns AppKit events into the event list.
  • src/platform/text_input.odin takes typing and the input method.
  • src/platform/blur.odin runs the blur behind the window.
  • src/ui/ui.odin holds the boxes and their kept state.
  • src/ui/layout.odin sizes and places the boxes.
  • src/ui/input.odin reads the mouse and the scroll.
  • src/ui/draw.odin turns the boxes into instances.
  • src/render/metal.odin draws the instances with Metal.
  • src/render/shaders.metal colours each pixel of a box, a glyph or a cover.
  • src/font/font.odin shapes text with CoreText.
  • src/font/atlas.odin draws glyphs from the glyph atlas.
  • src/icon/icon.odin draws SF Symbols from the icon atlas.
  • src/image/image.odin keeps the covers on the GPU.
  • src/image/load.odin downloads and decodes a cover on a worker thread.
  • src/app/kit/theme.odin holds the colours, the sizes and the accent.
  • src/app/kit/widgets.odin holds the small widgets.
  • src/app/kit/artwork.odin draws a cover over its placeholder.
